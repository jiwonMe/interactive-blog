## 왜 스프레드시트인가?

1979년, Dan Bricklin은 하버드 경영대학원 수업에서 교수가 칠판에 재무 모델을 그리는 것을 지켜보았다. 숫자 하나가 바뀌면 교수는 관련된 모든 숫자를 지우고 다시 계산해야 했다. Bricklin은 생각했다. "컴퓨터가 이걸 할 수 있지 않을까?"<Footnote id="visicalc-origin">Bricklin, Dan. "The Idea." _Bricklin.com_, http://www.bricklin.com/visicalc.htm</Footnote>

그가 Bob Frankston과 함께 만든 VisiCalc은 개인용 컴퓨터의 역사를 바꿨다. Apple II는 취미용 기기에서 비즈니스 도구가 됐다. "킬러 앱"이라는 개념이 탄생했다.

```
VisiCalc (1979):
>A1: 
    A         B         C         D         E
1   Revenue   Costs     Profit
2   1000      850       =A2-B2
3   1200      900       =A3-B3
```

45년이 지난 지금, 스프레드시트의 기본 인터페이스는 변하지 않았다. 격자, 셀 주소, 수식. Google Sheets와 Excel Online은 VisiCalc의 직계 후손이다.

**왜 변하지 않았을까?**

스프레드시트는 종이 원장(ledger)의 메타포를 완벽하게 디지털화했기 때문이다. 회계사들은 수백 년간 행과 열로 데이터를 정리해왔다. 스프레드시트는 그 멘탈 모델을 그대로 유지하면서 계산을 자동화했다. 새로운 UI를 배울 필요가 없었다.

이 시리즈에서 우리는 이 45년 된 인터페이스를 처음부터 만든다. 단순한 테이블이 아니다. 수식을 계산하고, 의존성을 추적하고, 수만 행을 부드럽게 렌더링하는 진짜 스프레드시트다.

## 우리가 만들 것

### 최종 목표

```
┌─────────────────────────────────────────────────┐
│  A1       │ =SUM(B2:B4)                         │
├─────┬──────────┬──────────┬──────────┬──────────┤
│     │    A     │    B     │    C     │    D     │
├─────┼──────────┼──────────┼──────────┼──────────┤
│  1  │  Name    │  Sales   │  Bonus   │  Total   │
├─────┼──────────┼──────────┼──────────┼──────────┤
│  2  │  Alice   │   1000   │  =B2*0.1 │ =B2+C2   │
├─────┼──────────┼──────────┼──────────┼──────────┤
│  3  │  Bob     │    850   │  =B3*0.1 │ =B3+C3   │
├─────┼──────────┼──────────┼──────────┼──────────┤
│  4  │  Carol   │   1200   │  =B4*0.1 │ =B4+C4   │
└─────┴──────────┴──────────┴──────────┴──────────┘
        ↑ B2를 수정하면 C2, D2, 그리고 A1이 자동으로 업데이트된다
```

### 여정의 구조

| 챕터 | 주제 | 핵심 도전 |
|------|------|----------|
| **1** | 격자와 인터랙션 | 컴포넌트 구조, 키보드 네비게이션 |
| **2** | 편집과 폼 상태 | 인라인 에디터, 상태 동기화 |
| **3** | 성능과 Virtualization | 100,000행을 60fps로 렌더링 |
| **4** | 수식 엔진 | 파서, AST, 인터프리터 구현 |
| **5** | 의존성 그래프 | 토폴로지 정렬, 순환 참조 탐지 |
| **6** | 히스토리 관리 | Command 패턴, Undo/Redo |
| **7** | 고급 UX | 범위 선택, 드래그 앤 드롭, 접근성 |

**Chapter 1-2**는 기초 공사다. React로 인터랙티브한 격자를 만든다.

**Chapter 3**부터 진짜 도전이 시작된다. 일반적인 테이블 라이브러리로는 불가능한, 스프레드시트만의 문제를 다룬다.

**Chapter 4-5**가 이 시리즈의 핵심이다. `=SUM(A1:A10)` 같은 수식을 파싱하고, 셀 간 의존성을 추적하며, 하나의 셀이 바뀌면 어떤 셀들을 다시 계산해야 하는지 알아내는 엔진을 만든다.

## 기술 스택

- **React 18**: 컴포넌트 기반 UI
- **TypeScript**: 타입 안전성
- **Vite**: 빠른 개발 환경
- **Vitest**: 테스트 프레임워크
- **CSS Modules**: 스코프된 스타일링

의도적으로 최소한의 의존성만 사용한다. 상태 관리 라이브러리, UI 프레임워크, 스프레드시트 라이브러리 없이 처음부터 만든다. 이래야 내부 동작을 완전히 이해할 수 있다.

## 프로젝트 설정

### 생성

```bash
npm create vite@latest spreadsheet -- --template react-ts
cd spreadsheet
npm install
```

### 테스트 환경

```bash
npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom
```

`vite.config.ts`:

```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: './src/test/setup.ts',
  },
});
```

`src/test/setup.ts`:

```typescript
import '@testing-library/jest-dom';
```

`package.json`에 스크립트 추가:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "test": "vitest",
    "test:coverage": "vitest run --coverage"
  }
}
```

### 폴더 구조

```
src/
├── components/     # React 컴포넌트
├── hooks/          # 커스텀 훅
├── types/          # TypeScript 타입
├── utils/          # 유틸리티 함수
├── engine/         # 수식 엔진 (Chapter 4~)
└── test/           # 테스트 설정
```

설정이 완료되면 `npm run dev`로 개발 서버를 시작할 수 있다.

## 개발 방법론

이 시리즈는 **Test-Driven Development(TDD)**를 따른다. 코드를 작성하기 전에 테스트를 먼저 작성한다.

```
Red    → 실패하는 테스트 작성
Green  → 테스트를 통과시키는 최소한의 코드
Refactor → 테스트가 통과하는 상태에서 코드 개선
```

TDD의 진짜 가치는 테스트 자체가 아니다. **설계를 강제**한다는 점이다. 테스트하기 어려운 코드는 대체로 설계가 잘못된 코드다. 테스트를 먼저 작성하면 자연스럽게 테스트 가능한(= 잘 설계된) 코드를 만들게 된다.

각 챕터에서 TDD 사이클을 반복하지만, 모든 테스트 코드를 보여주지는 않는다. 핵심 개념과 흥미로운 결정에 집중한다. 전체 코드는 GitHub 저장소에서 확인할 수 있다.
