## 격자의 본질

스프레드시트의 가장 기본적인 형태는 격자다. 행과 열이 교차하여 셀을 만든다. 이 구조는 1979년 VisiCalc에서 시작되어 지금까지 변하지 않았다.<Footnote id="visicalc">Bricklin, Dan. "VisiCalc: Information from its creators." _Bricklin.com_, http://www.bricklin.com/visicalc.htm</Footnote>

VisiCalc의 화면은 단순했다. 5개의 열(A-E)과 20개의 행이 한 화면에 표시됐다. 각 셀은 고정된 너비를 가졌고, 값이 길면 잘렸다. 화살표 키로 셀 사이를 이동했다. 이 기본 인터페이스는 45년이 지난 지금도 동일하다.

```
VisiCalc (1979):
>A1: 
    A         B         C         D         E
1   --------- --------- --------- --------- ---------
2   --------- --------- --------- --------- ---------
3   --------- --------- --------- --------- ---------
```

이번 챕터에서는 이 격자 구조를 만든다. 복잡한 기능 없이, 순수하게 데이터를 화면에 표시하는 것에 집중한다. 셀을 선택하거나 편집하는 기능은 다음 챕터에서 다룬다.

### 완성 목표

이번 챕터가 끝나면 다음과 같은 스프레드시트가 완성된다:

<GridDemo />

데이터가 화면에 표시되지만, 아직 사용자 인터랙션은 없다. 마우스를 올리면 배경색이 바뀌는 정도의 시각적 피드백만 제공한다.

## 1.1 컴포넌트 구조

### 합성의 원칙

React의 핵심 철학 중 하나는 합성(composition)이다.<Footnote id="react-thinking">React. "Thinking in React." _React Documentation_, https://react.dev/learn/thinking-in-react</Footnote> 복잡한 UI를 작은 컴포넌트로 나누고, 이를 조합하여 전체를 만든다. 각 컴포넌트는 하나의 책임만 가진다.

스프레드시트를 세 개의 컴포넌트로 분해한다:

```
Grid
 └─ Row
     └─ Cell
```

**Cell**은 가장 작은 단위다. 하나의 값을 표시한다.

**Row**는 셀들을 가로로 배치한다. 하나의 행 데이터를 받아서 여러 Cell을 렌더링한다.

**Grid**는 행들을 세로로 쌓는다. 전체 데이터를 받아서 여러 Row를 렌더링한다.

이 구조가 유일한 정답은 아니다. 모든 것을 하나의 컴포넌트로 만들 수도 있다. 하지만 분리하면 각 부분을 독립적으로 테스트하고 수정할 수 있다.

### 데이터 흐름

React에서 데이터는 위에서 아래로 흐른다.<Footnote id="react-props">React. "Passing Props to a Component." _React Documentation_, https://react.dev/learn/passing-props-to-a-component</Footnote> 부모 컴포넌트가 자식에게 props로 데이터를 전달한다:

```
App (데이터 소유)
 │
 └─ Grid (data prop)
     │
     └─ Row (cells prop)
         │
         └─ Cell (value prop)
```

이 단방향 데이터 흐름은 애플리케이션을 예측 가능하게 만든다. 버그가 발생하면 데이터의 출처를 추적하기 쉽다.

## 1.2 데이터 구조 설계

코드를 작성하기 전에 데이터의 형태를 정의한다. TypeScript의 타입 시스템은 컴파일 시점에 오류를 잡아준다.

`src/types/index.ts` 파일을 만든다:

```typescript
/**
 * 하나의 셀 데이터
 */
export interface CellData {
  value: string | number;
}

/**
 * 하나의 행 데이터
 */
export interface RowData {
  cells: CellData[];
}

/**
 * 전체 그리드 데이터
 */
export interface GridData {
  rows: RowData[];
}

/**
 * 셀의 위치
 */
export interface CellPosition {
  rowIndex: number;
  colIndex: number;
}
```

왜 `{ value: 'Alice' }` 형태로 감싸는가? 지금은 값만 있지만, 나중에 수식, 스타일, 포맷 같은 속성이 추가된다. 처음부터 객체로 만들어두면 확장이 쉽다.

## 1.3 Cell 컴포넌트

### 요구사항 정의

Cell은 스프레드시트의 가장 작은 단위다. 다음 요구사항을 충족해야 한다:

1. 텍스트 값을 표시할 수 있다
2. 숫자 값을 표시할 수 있다
3. 빈 값도 렌더링한다 (높이 유지)
4. 고정된 최소 너비와 높이를 가진다
5. 긴 텍스트는 잘리고 말줄임표가 표시된다
6. 마우스를 올리면 배경색이 변한다

### 리팩토링

코드를 개선할 부분이 있는지 검토한다.

빈 셀의 경우 내용이 완전히 비어 있다. 레이아웃은 유지되지만, 시각적으로 더 명확하게 만들 수 있다. non-breaking space를 넣으면 빈 셀임을 더 잘 알 수 있다.

먼저 테스트를 추가한다:

```typescript
it('displays non-breaking space for empty value', () => {
  render(<Cell value="" />);
  const cell = screen.getByTestId('cell');
  // \u00A0 = non-breaking space
  expect(cell.textContent).toBe('\u00A0');
});
```

테스트가 실패한다. 이제 구현을 수정한다:

```typescript
export function Cell({ value }: CellProps) {
  const displayValue = value === '' ? '\u00A0' : value;
  
  return (
    <div data-testid="cell" className={styles.cell}>
      {displayValue}
    </div>
  );
}
```

테스트가 통과한다. 리팩토링 완료다.

**CSS Modules 선택 이유**: 스타일링에는 여러 선택지가 있다. 인라인 스타일, 전역 CSS, CSS-in-JS 등. CSS Modules를 선택한 이유는 스타일 격리가 자동으로 되고, 런타임 오버헤드가 없기 때문이다.<Footnote id="css-modules">Maddern, Glen. "CSS Modules: Welcome to the Future." _glenmaddern.com_, 2015, https://glenmaddern.com/articles/css-modules</Footnote> 스프레드시트 스타일은 복잡하지 않으므로 이 정도면 충분하다.

## 1.4 Row 컴포넌트

### 요구사항 정의

Row는 여러 Cell을 가로로 배치한다:

1. 전달받은 셀 데이터를 모두 렌더링한다
2. 셀들을 가로로 나란히 배치한다
3. 빈 행도 렌더링한다
4. 행 인덱스를 data 속성으로 가진다 (디버깅, 테스트 용도)
5. 마우스를 올리면 행 전체 배경색이 변한다

### 테스트 작성

`src/components/__tests__/Row.test.tsx`:

### 구현

`src/components/Row.tsx`:

```typescript
import { Cell } from './Cell';
import type { CellData } from '../types';
import styles from './Row.module.css';

interface RowProps {
  cells: CellData[];
  rowIndex: number;
}

export function Row({ cells, rowIndex }: RowProps) {
  return (
    <div 
      data-testid={`row-${rowIndex}`}
      className={styles.row}
    >
      {cells.map((cell, colIndex) => (
        <Cell 
          key={`${rowIndex}-${colIndex}`}
          value={cell.value}
        />
      ))}
    </div>
  );
}
```

`src/components/Row.module.css`:

```css
.row {
  display: flex;
}

.row:hover {
  background: #f8f9fa;
}
```

테스트가 통과한다.

### 리팩토링

현재 코드는 충분히 간단하다. 리팩토링할 부분이 없다.

**key prop 선택**: React 리스트에서 key는 항목을 식별하는 데 사용된다.<Footnote id="react-lists">React. "Rendering Lists." _React Documentation_, https://react.dev/learn/rendering-lists#keeping-list-items-in-order-with-key</Footnote> 인덱스만 사용하면 항목 순서가 바뀔 때 문제가 생길 수 있다. 하지만 스프레드시트에서 셀 순서는 고정되어 있다. 행 2, 열 3의 셀은 항상 그 위치다. 따라서 `${rowIndex}-${colIndex}` 조합이 적절하다.

**Flexbox 선택**: CSS Grid도 가능하지만, Flexbox를 선택했다. 열 개수가 행마다 다를 수 있고, 열 너비를 동적으로 조절할 계획이기 때문이다. Flexbox가 이런 상황에 더 유연하다.

## 1.5 Grid 컴포넌트

### 요구사항 정의

Grid는 전체 스프레드시트를 구성한다:

1. 여러 행을 세로로 쌓아서 표시한다
2. 빈 그리드도 렌더링한다
3. 열 헤더(A, B, C...)를 선택적으로 표시한다
4. 행 번호(1, 2, 3...)를 선택적으로 표시한다
5. 테두리와 기본 스타일을 가진다

### 구현

`src/components/Grid.tsx`:

```typescript
import { Row } from './Row';
import type { GridData } from '../types';
import styles from './Grid.module.css';

interface GridProps {
  data: GridData;
  showHeaders?: boolean;
}

export function Grid({ data, showHeaders = false }: GridProps) {
  // 가장 긴 행의 열 개수를 기준으로 헤더 생성
  const maxColumns = Math.max(
    ...data.rows.map((row) => row.cells.length),
    0
  );

  // A, B, C, ... 형태의 열 헤더
  const columnHeaders = Array.from({ length: maxColumns }, (_, i) =>
    String.fromCharCode(65 + i)
  );

  return (
    <div data-testid="grid" className={styles.grid}>
      {showHeaders && (
        <div className={styles.header}>
          <div className={styles.cornerCell}></div>
          {columnHeaders.map((header) => (
            <div key={header} className={styles.headerCell}>
              {header}
            </div>
          ))}
        </div>
      )}
      {data.rows.map((row, rowIndex) => (
        <div key={rowIndex} className={styles.rowContainer}>
          {showHeaders && (
            <div className={styles.rowNumber}>{rowIndex + 1}</div>
          )}
          <Row cells={row.cells} rowIndex={rowIndex} />
        </div>
      ))}
    </div>
  );
}
```

`src/components/Grid.module.css`:

```css
.grid {
```

### 리팩토링

열 헤더 생성 로직을 살펴보자:

```typescript
const columnHeaders = Array.from({ length: maxColumns }, (_, i) =>
  String.fromCharCode(65 + i)
);
```

이 코드는 A-Z까지만 지원한다. 27번째 열부터는 `[`, `\` 같은 문자가 나온다. 실제 스프레드시트는 AA, AB, ... 형태를 사용한다.

지금 당장 고칠 필요는 없다. 26개 열이면 대부분의 용도에 충분하다. 하지만 나중에 확장해야 한다는 것을 기록해둔다:

```typescript
// TODO: 26개 이상의 열 지원 (AA, AB, ...)
const columnHeaders = Array.from({ length: maxColumns }, (_, i) =>
  String.fromCharCode(65 + i)
);
```

YAGNI(You Aren't Gonna Need It) 원칙이다.<Footnote id="yagni">Fowler, Martin. "Yagni." _martinfowler.com_, 2015, https://martinfowler.com/bliki/Yagni.html</Footnote> 필요할 때 구현하면 된다.

3. DOM 노드 개수 확인

### 테스트 작성

`src/components/__tests__/Grid.performance.test.tsx`:

```typescript
import { describe, it, expect } from 'vitest';
import { render } from '@testing-library/react';
import { Grid } from '../Grid';
import type { GridData } from '../../types';

function generateLargeGrid(rows: number, cols: number): GridData {
  return {
    rows: Array.from({ length: rows }, (_, rowIndex) => ({
      cells: Array.from({ length: cols }, (_, colIndex) => ({
        value: `R${rowIndex}C${colIndex}`,
      })),
    })),
  };
}

describe('Grid Performance Baseline', () => {
  it('renders 100 rows under 100ms', () => {
    const data = generateLargeGrid(100, 10);

    const startTime = performance.now();
    render(<Grid data={data} />);
    const endTime = performance.now();

    const renderTime = endTime - startTime;
    console.log(`100 rows: ${renderTime.toFixed(2)}ms`);

    expect(renderTime).toBeLessThan(100);
  });

  it('renders 1000 rows under 500ms', () => {
    const data = generateLargeGrid(1000, 10);

    const startTime = performance.now();
    render(<Grid data={data} />);
    const endTime = performance.now();

    const renderTime = endTime - startTime;
    console.log(`1000 rows: ${renderTime.toFixed(2)}ms`);

    expect(renderTime).toBeLessThan(500);
  });

  it('creates expected number of DOM nodes', () => {
    const data = generateLargeGrid(100, 10);
    const { container } = render(<Grid data={data} />);

    const cellCount = container.querySelectorAll('[data-testid="cell"]').length;
    console.log(`DOM cells for 100 rows: ${cellCount}`);

    // 100 rows × 10 cols = 1000 cells
    expect(cellCount).toBe(1000);
  });
});
```

테스트를 실행하면 현재 성능 기준이 출력된다:

```

1000 rows: 312.67ms
DOM cells for 100 rows: 1000
```

이 숫자는 Chapter 4에서 virtualization을 적용한 후와 비교할 기준이 된다.

## 1.10 이번 챕터 정리

### 만든 것

- **Cell**: 단일 값을 표시하는 컴포넌트
- **Row**: 셀들을 가로로 배치하는 컴포넌트
- **Grid**: 행들을 세로로 쌓고 헤더를 추가하는 컴포넌트
- **데이터 유틸리티**: 테스트 데이터 생성 함수

### TDD 사이클

각 컴포넌트마다 동일한 사이클을 반복했다:

1. **요구사항 정의**: 컴포넌트가 무엇을 해야 하는지 명확히 한다
2. **테스트 작성**: 요구사항을 테스트 코드로 변환한다
3. **구현**: 테스트를 통과시키는 최소한의 코드를 작성한다
4. **리팩토링**: 테스트가 통과하는 상태를 유지하면서 코드를 개선한다

### 현재의 한계

- 셀을 선택할 수 없다
- 키보드로 이동할 수 없다
- 내용을 편집할 수 없다
- 대규모 데이터에서 느리다
