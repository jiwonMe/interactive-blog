<Callout title="TL;DR">
- 45년간 유지된 스프레드시트 UX(격자, A1, Tab/Enter)를 **웹 UI로 재현**한다.
- 핵심은 “렌더링”보다 **선택(selection)과 키보드 모델**이다. 이게 없으면 편집/수식/히스토리는 시작도 못 한다.
- 웹에선 Tab을 가로채면 포커스를 “가둬”버리기 쉽다. 그래서 **정말 처리한 키만 preventDefault**한다. (Esc로 탈출)
</Callout>

## 격자의 본질

스프레드시트는 격자다. 행과 열이 교차하여 셀을 만든다. 이 구조는 1979년 VisiCalc에서 시작되어 지금까지 변하지 않았다.

```
VisiCalc (1979):
>A1: 
    A         B         C         D         E
1   --------- --------- --------- --------- ---------
2   --------- --------- --------- --------- ---------
3   --------- --------- --------- --------- ---------
```

왜 이 구조가 45년간 살아남았을까?

**종이 원장의 메타포**. 회계사들은 수백 년간 행과 열로 데이터를 정리해왔다. VisiCalc은 새로운 인터페이스를 발명하지 않았다. 익숙한 멘탈 모델을 디지털화했다. 사용자는 배울 것이 없었다.

**좌표계의 단순함**. `A1`, `B3`, `C10`. 누구나 이해할 수 있는 주소 체계다. "2행 3열"보다 "B2"가 짧고, 발음하기 쉽고, 수식에서 사용하기 편하다.<Footnote id="cell-notation">A1 표기법은 VisiCalc이 도입했다. Lotus 1-2-3은 R1C1 표기법을 추가했지만, A1이 표준으로 자리잡았다.</Footnote>

**무한 캔버스의 환상**. 화면에 보이는 것은 일부다. 스크롤하면 더 많은 셀이 나타난다. 사용자는 제약 없이 데이터를 펼칠 수 있다고 느낀다. 실제로 Excel은 16,384열 × 1,048,576행을 지원한다.

이번 챕터에서는 이 격자를 만든다. 그리고 선택과 키보드 네비게이션을 추가한다.

## 1.2 컴포넌트 구조

React의 합성(composition) 원칙을 따른다. 복잡한 UI를 작은 컴포넌트로 나누고 조합한다:

```
Grid
 └─ Row
     └─ Cell
```

**Cell**은 가장 작은 단위다. 하나의 값을 표시하고, 선택 상태를 시각적으로 표현한다.

**Row**는 셀들을 가로로 배치한다. 선택 정보를 각 셀에 전달한다.

**Grid**는 전체를 관장한다. 데이터를 렌더링하고, 선택 상태를 관리하고, 키보드 이벤트를 처리한다.

<Callout title="실험 1: Tab 트랩을 직접 느껴보기">
1. **아무 셀도 클릭하지 않은 상태**에서 Tab을 눌러보자. (포커스가 페이지의 다른 요소로 이동해야 한다)
2. 그 다음 **셀을 클릭**하고 Tab을 눌러보자. (이제는 “셀 이동”이 되어야 한다)
3. Esc를 눌러보자. (선택이 해제되고 포커스가 빠져나가야 한다)

스프레드시트는 Tab을 내부 이동에 쓰지만, 웹에서 Tab은 “탈출 키”다. 이 충돌을 어떻게 풀지(언제 `preventDefault`를 할지)가 Chapter 1의 첫 번째 설계 포인트다.
</Callout>

<Callout variant="warning" title="함정: 열 헤더 A..Z는 26개에서 깨진다">
아래 Grid 구현은 `String.fromCharCode(65 + i)`로 `A, B, C...`를 만든다. 이 방식은 26열을 넘으면 `[` 같은 문자가 나오면서 깨진다.

이건 “사소한 버그”가 아니라, **스프레드시트가 주소 체계를 어떻게 설계했는가**와 연결된 문제다. Chapter 5(엔진)로 갈수록 이 주소 체계가 핵심이 된다. (AA, AB, ...를 지원하는 변환을 나중에 제대로 구현한다)
</Callout>

<CollapsibleSection title="스프레드시트 주소 체계 맛보기: A1은 사실 26진법(같은데, 0이 없다)">
스프레드시트의 열은 숫자가 아니라 **알파벳**이다. 여기서 중요한 포인트는 두 가지다:

- **열 이름은 1-based**다: `A=1, B=2, ... Z=26`
- 그래서 `AA`는 “A 다음 A”가 아니라 **27**이다 (즉, 일반적인 0-based 26진법이 아니다)

예를 들어 열 인덱스(0-based)를 열 이름으로 바꾸면:

```
0 → A
1 → B
...
25 → Z
26 → AA
27 → AB
51 → AZ
52 → BA
```

이 작은 규칙이 Chapter 5에서 갑자기 큰 의미를 갖는다:

- `=SUM(B2:B4)`를 파싱하려면 **B, 2를 좌표로 바꿔야** 한다
- `AA10` 같은 참조를 만나면 열 변환이 필수다
- 범위(`B2:B4`)는 결국 “좌표 쌍”의 집합으로 풀린다

<CollapsibleCode title="colIndexToName(0-based) 구현 예시 (접기/펼치기)">
```typescript
// 0-based colIndex를 A1 표기 열 이름으로 변환
// 0 -> A, 25 -> Z, 26 -> AA
export function colIndexToName(colIndex: number): string {
  let n = colIndex + 1; // 1-based로 변환
  let result = '';

  while (n > 0) {
    n -= 1; // 1..26을 0..25로 맞춰준다 (여기가 핵심)
    const digit = n % 26;
    result = String.fromCharCode(65 + digit) + result;
    n = Math.floor(n / 26);
  }

  return result;
}
```
</CollapsibleCode>

이 함수는 지금 당장 완성도가 높아 보이지 않을 수 있다. 하지만 “왜 `n -= 1`이 들어가야 하는지”를 이해하면, A1 주소 체계의 핵심을 이해한 것이다.
</CollapsibleSection>

<Callout title="결정: 키보드 이벤트는 ‘전역’이 아니라 ‘그리드’에만">
키보드 이벤트를 `window`에 붙이면 편하지만, 페이지 전체 단축키/입력 UX와 충돌하기 쉽다. 그래서 이 데모는 **그리드가 포커스를 가진 동안에만** 키 입력을 처리한다.

결과적으로 `tabIndex={0}`과 “클릭 후 focus()”가 필수가 된다. (스프레드시트 UX는 결국 포커스 모델을 설계하는 일이다)
</Callout>

### Cell (코드는 접어두기)

<CollapsibleCode title="Cell 코드 (접기/펼치기)">
```typescript
// src/components/Cell.tsx
import styles from './Cell.module.css';

interface CellProps {
  value: string | number;
  isSelected?: boolean;
  onClick?: () => void;
}

export function Cell({ value, isSelected = false, onClick }: CellProps) {
  const displayValue = value === '' ? '\u00A0' : value;
  
  const className = [
    styles.cell,
    isSelected && styles.selected,
  ].filter(Boolean).join(' ');
  
  return (
    <div 
      className={className}
      onClick={onClick}
      role="gridcell"
      aria-selected={isSelected}
    >
      {displayValue}
    </div>
  );
}
```
</CollapsibleCode>

**빈 셀 처리**: 빈 문자열은 `\u00A0`(non-breaking space)로 대체한다. 이래야 셀 높이가 유지된다.

**`role="gridcell"`**: 스크린 리더가 이 요소를 스프레드시트 셀로 인식한다. 접근성은 나중에 추가하는 게 아니라 처음부터 고려해야 한다.

### Row (코드는 접어두기)

<CollapsibleCode title="Row 코드 (접기/펼치기)">
```typescript
// src/components/Row.tsx
import { Cell } from './Cell';
import type { CellData, Selection } from '../types';
import styles from './Row.module.css';

interface RowProps {
  cells: CellData[];
  rowIndex: number;
  selection?: Selection;
  onCellClick?: (rowIndex: number, colIndex: number) => void;
}

export function Row({ cells, rowIndex, selection, onCellClick }: RowProps) {
  return (
    <div className={styles.row} role="row">
      {cells.map((cell, colIndex) => {
        const isSelected = 
          selection?.rowIndex === rowIndex && 
          selection?.colIndex === colIndex;

        return (
          <Cell 
            key={colIndex}
            value={cell.value}
            isSelected={isSelected}
            onClick={() => onCellClick?.(rowIndex, colIndex)}
          />
        );
      })}
    </div>
  );
}
```
</CollapsibleCode>

Row는 선택 상태를 "아는" 게 아니라 "전달받는다". 자신의 행 인덱스와 비교하여 각 셀에 `isSelected`를 계산해 넘긴다.

### Grid (코드는 접어두기)

<CollapsibleCode title="Grid 코드 (접기/펼치기)">
```typescript
// src/components/Grid.tsx
import { useRef, useEffect } from 'react';
import { Row } from './Row';
import { useSelection } from '../hooks/useSelection';
import { useKeyboard } from '../hooks/useKeyboard';
import type { GridData } from '../types';
import styles from './Grid.module.css';

interface GridProps {
  data: GridData;
  showHeaders?: boolean;
}

export function Grid({ data, showHeaders = false }: GridProps) {
  const gridRef = useRef<HTMLDivElement>(null);
  
  const totalRows = data.rows.length;
  const totalCols = Math.max(...data.rows.map(r => r.cells.length), 0);

  const { selection, selectCell, clearSelection, moveSelection } = useSelection(
    totalRows,
    totalCols
  );

  const { handleKeyDown } = useKeyboard({
    onArrowUp: () => {
      if (!selection) return false;
      moveSelection('up');
      return true;
    },
    onArrowDown: () => {
      if (!selection) return false;
      moveSelection('down');
      return true;
    },
    onArrowLeft: () => {
      if (!selection) return false;
      moveSelection('left');
      return true;
    },
    onArrowRight: () => {
      if (!selection) return false;
      moveSelection('right');
      return true;
    },
    onTab: (shift) => {
      if (!selection) return false;
      moveSelection(shift ? 'left' : 'right');
      return true;
    },
    onEnter: (shift) => {
      if (!selection) return false;
      moveSelection(shift ? 'up' : 'down');
      return true;
    },
    onEscape: () => {
      // 키보드로 그리드를 빠져나갈 “탈출구”
      if (!selection) return false;
      clearSelection();
      gridRef.current?.blur();
      return true;
    },
  });

  useEffect(() => {
    const el = gridRef.current;
    if (el) {
      el.addEventListener('keydown', handleKeyDown);
      return () => el.removeEventListener('keydown', handleKeyDown);
    }
  }, [handleKeyDown]);

  const handleCellClick = (rowIndex: number, colIndex: number) => {
    selectCell({ rowIndex, colIndex });
    gridRef.current?.focus();
  };

  const columnHeaders = Array.from({ length: totalCols }, (_, i) =>
    String.fromCharCode(65 + i)
  );

  return (
    <div 
      ref={gridRef}
      className={styles.grid}
      tabIndex={0}
      role="grid"
      aria-rowcount={totalRows}
      aria-colcount={totalCols}
    >
      {showHeaders && (
        <div className={styles.header}>
          <div className={styles.cornerCell} />
          {columnHeaders.map(h => (
            <div key={h} className={styles.headerCell}>{h}</div>
          ))}
        </div>
      )}
      {data.rows.map((row, rowIndex) => (
        <div key={rowIndex} className={styles.rowContainer}>
          {showHeaders && (
            <div className={styles.rowNumber}>{rowIndex + 1}</div>
          )}
          <Row 
            cells={row.cells} 
            rowIndex={rowIndex}
            selection={selection}
            onCellClick={handleCellClick}
          />
        </div>
      ))}
    </div>
  );
}
```
</CollapsibleCode>

**`tabIndex={0}`**: 이 속성이 있어야 div가 포커스를 받을 수 있다. 포커스가 없으면 키보드 이벤트가 발생하지 않는다.<Footnote id="tabindex">MDN Web Docs. "tabindex." https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/tabindex</Footnote>

**`gridRef.current?.focus()`**: 셀을 클릭한 후 그리드에 포커스를 준다. 이래야 바로 방향키로 이동할 수 있다.

## 1.3 키보드 철학

왜 Tab은 오른쪽이고 Enter는 아래일까?

이건 임의의 선택이 아니다. 1979년 VisiCalc부터 2024년 Google Sheets까지, 이 동작은 변하지 않았다.

데이터 입력 워크플로우를 생각해보자:

```
┌──────────┬──────────┬──────────┐
│  Name    │   Age    │  Status  │  ← 가로: 같은 레코드의 다른 필드
├──────────┼──────────┼──────────┤
│  Alice   │    30    │  Active  │  ← Tab으로 이동
├──────────┼──────────┼──────────┤
│  Bob     │    25    │ Inactive │
├──────────┼──────────┼──────────┤
│  Carol   │    35    │  Active  │
└──────────┴──────────┴──────────┘
     ↑
   세로: 같은 필드의 다른 레코드
   Enter로 이동
```

**Tab은 같은 레코드 내 이동**. 한 사람의 정보(이름 → 나이 → 상태)를 연속으로 입력할 때 사용한다.

**Enter는 다음 레코드로 이동**. 한 필드를 여러 사람에게 입력할 때(Alice → Bob → Carol) 사용한다.

이 구분은 사용자가 의식하지 않아도 자연스럽게 느껴진다. 45년간 검증된 UX 패턴이다.

### useSelection 훅

<CollapsibleCode title="useSelection 훅 코드 (접기/펼치기)">
```typescript
// src/hooks/useSelection.ts
import { useState, useCallback } from 'react';
import type { Selection, CellPosition } from '../types';

export function useSelection(totalRows: number, totalCols: number) {
  const [selection, setSelection] = useState<Selection>(null);

  const selectCell = useCallback((position: CellPosition) => {
    setSelection(position);
  }, []);

  const clearSelection = useCallback(() => {
    setSelection(null);
  }, []);

  const moveSelection = useCallback(
    (direction: 'up' | 'down' | 'left' | 'right') => {
      setSelection((current) => {
        if (!current) return null;

        const { rowIndex, colIndex } = current;

        switch (direction) {
          case 'up':
            return { rowIndex: Math.max(0, rowIndex - 1), colIndex };
          case 'down':
            return { rowIndex: Math.min(totalRows - 1, rowIndex + 1), colIndex };
          case 'left':
            return { rowIndex, colIndex: Math.max(0, colIndex - 1) };
          case 'right':
            return { rowIndex, colIndex: Math.min(totalCols - 1, colIndex + 1) };
        }
      });
    },
    [totalRows, totalCols]
  );

  return { selection, selectCell, clearSelection, moveSelection };
}
```
</CollapsibleCode>

경계 처리가 핵심이다. `Math.max`와 `Math.min`으로 그리드 범위를 벗어나지 않게 한다. 첫 행에서 위로 가면 그대로, 마지막 열에서 오른쪽으로 가면 그대로.

### useKeyboard 훅

<CollapsibleCode title="useKeyboard 훅 코드 (접기/펼치기)">
```typescript
// src/hooks/useKeyboard.ts
import { useCallback } from 'react';

interface KeyboardHandlers {
  onArrowUp?: () => boolean;
  onArrowDown?: () => boolean;
  onArrowLeft?: () => boolean;
  onArrowRight?: () => boolean;
  onTab?: (shiftKey: boolean) => boolean;
  onEnter?: (shiftKey: boolean) => boolean;
  onEscape?: () => boolean;
}

export function useKeyboard(handlers: KeyboardHandlers) {
  const handleKeyDown = useCallback((event: KeyboardEvent) => {
    const { key, shiftKey } = event;

    let handled = false;

    switch (key) {
      case 'ArrowUp':
        handled = handlers.onArrowUp?.() ?? false;
        break;
      case 'ArrowDown':
        handled = handlers.onArrowDown?.() ?? false;
        break;
      case 'ArrowLeft':
        handled = handlers.onArrowLeft?.() ?? false;
        break;
      case 'ArrowRight':
        handled = handlers.onArrowRight?.() ?? false;
        break;
      case 'Tab':
        handled = handlers.onTab?.(shiftKey) ?? false;
        break;
      case 'Enter':
        handled = handlers.onEnter?.(shiftKey) ?? false;
        break;
      case 'Escape':
        handled = handlers.onEscape?.() ?? false;
        break;
    }

    // 정말 “우리가 처리한 경우”에만 브라우저 기본 동작을 막는다.
    if (handled) event.preventDefault();
  }, [handlers]);

  return { handleKeyDown };
}
```
</CollapsibleCode>

<Callout variant="warning" title="함정: Tab을 가로채면 포커스가 갇힌다">
웹에서 Tab은 “다음 포커스 가능한 요소로 이동”이라는 강력한 기본 동작을 가진다. 스프레드시트처럼 Tab을 “셀 이동”에 쓰려면 `preventDefault()`가 필요하다.

하지만 **무조건** `preventDefault()`를 걸면 문제가 생긴다:

- 아직 셀이 선택되지 않았는데도 Tab이 막혀서, 사용자가 그리드에서 빠져나갈 수 없다
- 스크린 리더/키보드 사용자에게 특히 치명적이다

그래서 위 구현은 **핸들러가 실제로 키를 처리한 경우에만** `preventDefault()`를 호출한다. 또한 “Esc로 탈출”을 제공한다.
</Callout>

**`event.preventDefault()`**: 브라우저 기본 동작을 막는다. Tab이 다음 요소로 포커스를 옮기거나, Enter가 폼을 제출하는 것을 방지한다. 중요한 건 “언제 막을 것인가”다.

**핸들러가 없으면 무시**: `onTab`이 등록되지 않으면 Tab 키는 원래대로 동작한다. 필요한 키만 선택적으로 가로챌 수 있다.

<CollapsibleSection title="더 깊게 보기(선택): 웹 접근성 규범에서 Tab은 ‘탈출 키’다">
WAI-ARIA의 grid 패턴에서는 보통 **Tab은 그리드 안으로 들어오고/빠져나가는 용도**, **방향키는 그리드 내부 이동** 용도로 권한다.

하지만 스프레드시트는 역사적으로 Tab/Enter를 내부 이동에 사용한다. 우리는 “스프레드시트 UX”를 우선한다. 대신 “탈출”을 제공해야 한다:

- **Esc**: 그리드 네비게이션 모드를 종료(선택 해제 + blur)
- (추후 Chapter 8) 스크린 리더를 위한 별도 단축키/설명 제공

이 지점이 “웹 위젯”과 “스프레드시트”가 충돌하는 대표적인 트레이드오프다.
</CollapsibleSection>

## 1.4 스타일링

CSS Modules를 사용한다. 클래스 이름이 자동으로 해시되어 충돌이 없다.

여기서 셀 크기를 고정(`width`, `height`)으로 둔 이유는 단지 “보기 좋게” 만들기 위해서가 아니다. **Chapter 3의 virtualization**에서 이 결정이 큰 이득이 된다. 셀 크기가 고정이면 “n번째 행이 화면에서 몇 px 위치인가?”를 \(n \times rowHeight\)로 \(O(1)\)에 계산할 수 있다. 반대로 가변 높이를 허용하면 스크롤 오프셋 계산이 복잡해지고, 캐싱/측정이 필요해진다.

<CollapsibleCode title="Cell.module.css (접기/펼치기)">
```css
/* src/components/Cell.module.css */

.cell {
  width: 100px;
  height: 32px;
  padding: 0 8px;
  border: 1px solid #e4e4e7;
  display: flex;
  align-items: center;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  background: white;
  font-size: 14px;
  cursor: pointer;
  transition: background-color 0.15s ease;
}

.cell:hover {
  background: #f4f4f5;
}

.selected {
  outline: 2px solid #1a73e8;
  outline-offset: -2px;
  background: #e8f0fe;
  position: relative;
  z-index: 1;
}
```
</CollapsibleCode>

**`outline` vs `border`**: 선택 표시에 `outline`을 사용한다. `border`를 사용하면 요소 크기가 변하거나 레이아웃이 밀린다. `outline`은 레이아웃에 영향을 주지 않는다.<Footnote id="outline">MDN Web Docs. "outline." https://developer.mozilla.org/en-US/docs/Web/CSS/outline</Footnote>

**`z-index: 1`**: 선택된 셀의 outline이 인접 셀 위에 표시되도록 한다.

<CollapsibleCode title="Grid.module.css (접기/펼치기)">
```css
/* src/components/Grid.module.css */

.grid {
  display: inline-block;
  border: 1px solid #d4d4d8;
  border-radius: 0.5rem;
  overflow: hidden;
  outline: none;
}

.grid:focus {
  box-shadow: 0 0 0 2px #1a73e8;
}

.grid:focus:not(:focus-visible) {
  box-shadow: none;
}
```
</CollapsibleCode>

**`:focus-visible`**: 키보드로 포커스했을 때만 테두리를 표시한다. 마우스 클릭으로 포커스해도 테두리가 보이면 거슬린다.<Footnote id="focus-visible">MDN Web Docs. ":focus-visible." https://developer.mozilla.org/en-US/docs/Web/CSS/:focus-visible</Footnote>

## 1.5 정리

### 만든 것

- **데이터 구조**: CellPosition, CellData, RowData, GridData, Selection
- **컴포넌트**: Cell, Row, Grid
- **훅**: useSelection, useKeyboard
- **스타일**: CSS Modules로 스코프된 스타일링

### 설계 결정

| 결정 | 이유 |
|------|------|
| Cell → Row → Grid 분리 | 각 부분을 독립적으로 테스트/수정 가능 |
| 선택 상태를 Grid가 관리 | 단일 진실 공급원 (Single Source of Truth) |
| outline으로 선택 표시 | 레이아웃에 영향 없음 |
| tabIndex={0} | div가 포커스를 받을 수 있게 함 |
| Tab/Enter 방향 분리 | 45년간 검증된 UX 패턴 |

### 현재의 한계

- 셀 내용을 편집할 수 없다
- 대량의 데이터에서 느릴 수 있다 (virtualization 없음)
- 수식을 계산할 수 없다
