> "이상하게 점심 룰렛 돌리면 A랑 B가 맨날 같이 걸리는 것 같은데..."

회사에서 점심 메뉴 룰렛을 몇 번 돌리다 보니, 슬랙에 이런 의문이 올라왔다. 처음엔 "그냥 운이겠지"라고 넘겼는데, 몇 번 더 돌려보니 정말 특정 사람들끼리 자주 뭉쳐 나온다. 셔플 알고리즘 자체에 문제가 있는 건 아닐까?

그 의문이 이 글의 시작점이다.

Mike Bostock의 Will It Shuffle?<Footnote>https://bost.ocks.org/mike/shuffle/compare.html</Footnote>은 셔플 알고리즘의 편향성을 시각적으로 잘 설명한 글이다. 이 글에서는 D3.js와 React로 같은 시각화를 구현하고, 잘못된 셔플이 왜 문제인지, 그리고 Fisher-Yates가 왜 공정한지 눈으로 확인해본다.

## 셔플의 공정성

완벽한 셔플이라면 모든 요소가 모든 위치에 동일한 확률로 배치되어야 한다. $N$개 요소가 있다면 특정 요소가 특정 위치에 올 확률은 정확히 $1/N$이다.

이 조건을 만족하지 못하면 **편향(Bias)**이 있다고 한다.

### 1. Random Comparator (나쁜 예)

가장 흔한 실수가 `array.sort(() => Math.random() - 0.5)` 코드다.

```javascript
// ❌ 쓰지 마라
function randomComparatorShuffle(array) {
  return array.sort(() => Math.random() - 0.5);
}
```

시각화에서 **Random Comparator**를 선택해보자. 대각선 패턴이 뚜렷하게 나타난다. 요소들이 원래 위치 근처에 머무르거나, 특정 위치로 쏠린다는 뜻이다.

#### 왜 실패하는가

`sort`는 **일관된 비교 함수**를 전제로 동작한다. `Math.random()` 기반 비교는 이 전제를 깨뜨려서 엔진마다 다른 편향을 만든다<Footnote>https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Array/sort</Footnote>.

정렬 알고리즘은 비교 함수가 다음을 만족한다고 가정한다:

1. **반사성**: `compare(a, a) = 0`
2. **반대칭성**: `compare(a, b) < 0`이면 `compare(b, a) > 0`
3. **추이성**: $a \lt b$이고 $b \lt c$이면 $a \lt c$

`() => Math.random() - 0.5`는 이 속성들을 만족하지 않는다. 특히 추이성이 깨진다:

- 첫 번째 비교: $a < b$ (확률 0.5)
- 두 번째 비교: $b < c$ (확률 0.5)
- 세 번째 비교: $c < a$ (확률 0.5) ← 모순!

비교 결과가 일관되지 않으니 정렬 알고리즘 동작이 예측 불가능해진다.

V8(Chrome/Node.js)은 TimSort를 쓰는데, 이미 정렬된 구간(run)을 활용해 빠르게 정렬한다. 랜덤 comparator를 쓰면 이 최적화 흔적이 남아서 **요소가 원래 위치 근처에 머무르는 경향**이 생긴다<Footnote>https://v8.dev/blog/array-sort</Footnote>. 시각화에서 대각선이 진하게 보이는 이유다.

결국 `sort(() => Math.random() - 0.5)`는 겉보기엔 섞이는 것 같아도, **공정한 셔플이 아니다**.

### 2. Naive Swap (나쁜 예)

또 다른 실수는 모든 요소를 임의의 위치와 교환하는 방식이다.

```javascript
// ❌ 미묘하게 편향된다
function naiveSwapShuffle(array) {
  const n = array.length;
  for (let i = 0; i < n; i++) {
    const j = Math.floor(Math.random() * n); // 아무 인덱스나
    swap(array, i, j);
  }
}
```

얼핏 공정해 보이지만, 이 방식은 $N^N$가지 경우의 수를 만든다. 가능한 순열은 $N!$가지인데, $N^N$이 $N!$로 나누어떨어지지 않으니 **어떤 순열은 더 자주 나올 수밖에 없다**.

비유하자면, 이 알고리즘은 $N$번의 무작위 선택을 하고 그 결과를 하나의 순열로 "압축"하는 구조다. 문제는 여러 선택 경로가 같은 순열로 압축되는데, 그 개수가 순열마다 다르다는 점이다.

시각화에서 **Naive Swap**을 선택해보자. 언뜻 괜찮아 보여도 반복 횟수를 늘리면 미세한 편향이 드러난다.

### 3. Fisher-Yates Shuffle (좋은 예)

올바른 방법은 Fisher-Yates(또는 Knuth) 셔플이다.

```javascript
// ✅ 공정한 셔플
function fisherYatesShuffle(array) {
  let m = array.length, t, i;
  while (m) {
    i = Math.floor(Math.random() * m--); // 남은 요소 중에서 선택
    t = array[m];
    array[m] = array[i];
    array[i] = t;
  }
  return array;
}
```

이 알고리즘은 수학적으로 완벽하게 공정하다. 시각화에서 **Fisher-Yates**를 선택하면 전체가 균일한 회색 노이즈로 채워진다.

### Fisher-Yates의 수학적 증명

Fisher-Yates가 공정한 이유를 귀납법으로 증명해보자.

#### 목표

$N$개 요소에 Fisher-Yates를 적용하면 $N!$개 순열이 각각 $1/N!$ 확률로 나온다.

#### 알고리즘

- **$k$번째 단계** ($k = N, N-1, \ldots, 1$):
  - 인덱스 $0$부터 $k-1$ 중 하나를 무작위로 선택 (확률 $1/k$)
  - 선택한 인덱스와 $k-1$ 위치의 요소를 교환

#### 증명

**기저**: $N = 1$이면 순열은 1개뿐이고 확률은 $1/1! = 1$이다.

**귀납 가정**: $N = k-1$일 때 모든 $(k-1)!$개 순열이 각각 $1/(k-1)!$ 확률로 나온다고 가정하자.

**귀납 단계**: $N = k$일 때를 보자.

1. 마지막 위치에 올 요소를 $k$개 중 하나로 선택한다. 각 요소가 선택될 확률은 $1/k$다.
2. 나머지 $k-1$개 요소는 귀납 가정에 의해 각 순열이 $1/(k-1)!$ 확률로 나온다.

따라서 특정 순열이 나올 확률은:

$$\frac{1}{k} \times \frac{1}{(k-1)!} = \frac{1}{k!}$$

$k!$개 순열 모두 같은 확률로 나온다.

#### 개별 위치의 확률

특정 요소 $e$가 위치 $j$에 올 확률도 $1/N$이다.

$e$가 $j$에 고정되면 나머지 $N-1$개의 배치는 $(N-1)!$가지다. 각 순열 확률이 $1/N!$이므로:

$$(N-1)! \times \frac{1}{N!} = \frac{1}{N}$$

모든 요소가 모든 위치에 $1/N$ 확률로 배치된다.

#### Naive Swap이 실패하는 이유

Naive Swap은 $N$번의 선택에서 매번 $N$개 중 하나를 고른다.

- 선택 경로의 수: $N^N$
- 가능한 순열의 수: $N!$

$N^N$이 $N!$로 나누어떨어지지 않는다. 예를 들어 $3^3 = 27$이고 $3! = 6$인데, 27은 6으로 나누어떨어지지 않는다. 그래서 어떤 순열은 $5/27$, 어떤 순열은 $4/27$ 확률을 갖게 된다.

#### 핵심

Fisher-Yates는 각 단계에서 **아직 배치되지 않은 요소들 중에서만** 고르기 때문에 정확히 $N!$개 경로가 생기고, 각 경로가 하나의 순열에 1:1로 대응한다. 그래서 공정하다.

## 결론

셔플 알고리즘의 작은 차이가 결과 분포에 큰 영향을 준다. 게임, 암호화, 샘플링처럼 무작위성이 중요한 곳에서는 반드시 검증된 알고리즘을 써야 한다.

**핵심 규칙:**

1. **`array.sort(() => Math.random() - 0.5)` 쓰지 마라**. 편향이 생긴다.

2. **Fisher-Yates를 써라**. 대부분의 언어와 라이브러리에 이미 구현되어 있다.
